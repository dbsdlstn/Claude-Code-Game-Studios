# 사건 목록(event registry) 명세: 한 사건 한 덱 규칙의 검사

> **상태**: 초안(2026-11-05, D125). 가야 모델(`design/gaya-timeline-model.md`, D96 흡수안 채택)에서 나온 "한 사건은 한 덱에만 둔다" 규칙을 **검증기가 잡을 수 있게** 하는 명세다. 구현(`tools/validate_cards_v2.py` 확장, 사건 목록 파일 작성)은 콘텐츠 세션 몫이다.
> **근거**: `design/content-plan-m2.md`, `design/card-data-schema-v2.md`, 저장소의 현재 카드 84장 점검(§6).
> **원칙**: 검증기는 **판정이 아니라 관찰을 낸다**(`.claude/docs/context-management.md`의 스크립트 규칙). 단 `event_key` 중복처럼 **결정적으로 틀린 것**만 오류로 두고, 휴리스틱(같은 연도 + 같은 주제)은 항상 관찰 줄(OBS)만 낸다.
> **한계**: 아래 중복 후보는 카드 제목·연도·주제만 보고 찾은 것이며 지문과 해설을 읽고 같은 사건인지 판단한 것이 아니다.

## 1. 규칙

1. **한 사건은 한 덱에만 카드로 둔다.** 같은 사건을 두 나라 덱에서 각자 카드로 만들면 (a) 한 덱의 카드를 본 뒤 다른 덱의 카드가 정답이 거의 보이고(정답 노출), (b) 같은 사건의 학습 횟수가 두 번 세어지고, (c) 사실 확인이 두 번 필요하다.
2. **소유 덱(owner)**은 사건의 **행위자 나라**다(전쟁은 공격한 쪽, 외교는 요청·시행한 쪽, 제도는 시행한 나라). 판단이 갈리면 지문의 주어 나라, 그래도 갈리면 기출 서술이 쓰는 관점을 따른다. 소유 덱을 정하는 것은 콘텐츠 세션이다.
3. **소유하지 않는 덱**은 카드를 만들지 않는다. 대신 그 덱의 관련 카드 **해설**이 사건을 언급할 수 있다(카드가 아니라 설명).
4. **예외: 관점 쌍(perspective pair)**. 같은 사건이지만 **서로 다른 왕 칸을 묻는** 두 카드가 시험에서 모두 가치가 있을 때만(예: 같은 해 한성 함락이 고구려 장수왕 칸과 백제 개로왕·문주왕 칸에 각각 놓임) 두 카드를 허용한다. 사건 목록에 **쌍으로 명시**하고 이유를 적는다. 쌍의 두 카드는 **같은 세션에 함께 내지 않는다**(한 카드가 다른 카드의 정답을 알려 주지 않게; 웹 구현 몫).
5. **다른 사건인데 연도가 같은 경우**(예: 642년 대야성 공격과 연개소문의 정변)는 문제가 아니다. 사건 목록에 서로 다른 키로 등록하면 된다.

## 2. 사건 키 (`event_key`)

모든 사료 카드에 선택 필드 `event_key`를 둔다(M3 시작 전에 전 카드에 채우고 그때부터 필수).

- 형식: `^[a-z0-9]+(-[a-z0-9]+)*$`. 관례: `<연도>-<영문 슬러그>`. 기원전은 `bc<연도>-…`. 예: `400-silla-relief`, `475-hanseong-fall`, `532-geumgwan-annex`.
- 연도는 카드의 `year`와 같게 쓴다(검증 E5). 이설이 있는 사건도 카드의 정답 연도를 쓴다.
- 키는 **플레이어에게 보이지 않는다**(정답 노출 없음). 카드 `id`와 별개이며 한 번 정하면 바꾸지 않는다(참조 안정).
- 슬러그는 사건을 가리키는 짧은 영어 단어. 왕 이름을 넣어도 되지만 화면에 나오지 않으므로 정답 노출 규칙(V8)과 무관하다.

## 3. 사건 목록 파일 (`assets/data/cards/v2/events.json`)

기계가 읽는 단일 파일. 사람이 읽는 해설은 같은 키로 `design/exam-topics/*.md`에 두거나 파일의 `note`에 적는다.

```json
{
  "schema": 1,
  "events": [
    { "key": "400-silla-relief", "year": 400, "title": "광개토왕의 신라 구원",
      "owner_card": "goguryeo-src-08", "participants": ["goguryeo", "silla", "gaya"],
      "status": "owned", "note": "행위자 고구려. 신라 덱의 원군 카드는 해설로 흡수" },
    { "key": "475-hanseong-fall", "year": 475, "title": "한성 함락과 개로왕 전사",
      "owner_card": "goguryeo-src-10", "participants": ["goguryeo", "baekje"],
      "status": "perspective_pair", "pair_cards": ["goguryeo-src-10", "baekje-src-05"],
      "pair_reason": "장수왕 칸(고구려)과 개로왕·문주왕 칸(백제)을 각각 묻는 출제 가능성", "note": "" },
    { "key": "642-daeya-attack", "year": 642, "title": "백제의 대야성 공격",
      "owner_card": "baekje-src-12", "participants": ["baekje", "silla"], "status": "owned" }
  ],
  "distinct_pairs": [
    { "cards": ["baekje-src-23", "silla-src-12"], "reason": "황산벌 전투와 사비성 함락은 다른 사건" }
  ]
}
```

| 필드 | 설명 |
|---|---|
| `key` | 사건 키(2절). 목록에서 고유 |
| `year` | 정답 연도(카드와 같음) |
| `title` | 사건 이름(사람용) |
| `owner_card` | 소유 카드 id. `status`가 `planned`면 null 허용 |
| `participants` | 관련 나라(`goguryeo/baekje/silla/gaya` …) |
| `status` | `owned`(카드 있음) / `planned`(조사 중, 카드 없음) / `perspective_pair`(관점 쌍, `pair_cards` 필수) / `absorbed`(카드 없이 해설로만 다룸) |
| `pair_cards`, `pair_reason` | 관점 쌍일 때 두 카드 id와 이유 |
| `distinct_pairs` | "같은 연도·같은 주제지만 다른 사건"으로 확인한 카드 쌍(휴리스틱 경고를 끈다) |

## 4. 검증 규칙 (`tools/validate_cards_v2.py` 확장)

번호는 기존 V1~V15와 변형 명세 V16~V21과 겹치지 않게 **E**로 시작한다.

| # | 규칙 | 수준 |
|---|---|---|
| E1 | 모든 사료 카드가 `event_key`를 가진다 | M3 전: 경고, M3부터: **오류** |
| E2 | `event_key` 형식이 2절과 맞다 | 오류 |
| E3 | **한 `event_key`를 가진 카드가 서로 다른 덱에 둘 이상이면 오류**(관점 쌍으로 등록된 쌍은 제외) | **오류** |
| E4 | 카드의 `event_key`가 사건 목록에 있고, 목록의 `owner_card`(또는 `pair_cards`)가 그 카드와 일치한다 | 오류 |
| E5 | 사건 목록의 `year`가 카드의 `year`와 같다(`year_alt`와 일치하는 것은 허용하지 않는다: 정답 연도만) | 오류 |
| E6 | `participants`에 소유 카드의 `nation`이 들어 있다 | 오류 |
| E7 | `status: perspective_pair`이면 `pair_cards`가 정확히 2개이고 서로 다른 덱이며 둘 다 같은 `event_key`를 가진다. `pair_reason`이 비어 있지 않다 | 오류 |
| E8 | 사건 목록의 `owned` 항목마다 소유 카드가 실제로 존재한다. `planned`는 카드가 없어도 된다 | `owned`인데 카드 없음: 오류 |

**관찰(OBS, 오류 아님)**: 
- **중복 의심**: 서로 다른 덱의 두 사료 카드가 **같은 `year`이고 `exam_tags`가 하나 이상 겹치며** 서로 다른 `event_key`를 가지고 `distinct_pairs`에 없으면 "같은 사건일 수 있음" 줄로 출력한다. 제목이 달라도 잡히도록 제목 비교는 쓰지 않는다.
- 사건 목록에 없는 `event_key`를 가진 카드의 수, `planned` 사건의 수, 덱별 소유 카드 수, 관점 쌍의 수.
- 키가 비어 있는 카드의 수(E1 경고 단계).

## 5. 운영 절차

1. 카드를 새로 쓰기 **전에** 사건 목록에 키를 올린다(`planned`). 이미 같은 사건이 목록에 있으면 새 카드를 쓰지 않는다(소유 덱 카드의 해설에 흡수).
2. 카드를 쓰면 `status`를 `owned`로 바꾸고 `owner_card`를 채운다.
3. 이미 있는 카드는 **일괄 이관**한다: 모든 카드에 `event_key`를 채우고(M3 전) 사건 목록을 만든 뒤 `--strict`(E1 오류)로 바꾼다. 이관은 기계적으로 하기 어려우므로 콘텐츠 세션이 덱별로 한다.
4. 소유 덱이 정해졌는데 다른 덱에 같은 사건 카드가 이미 있으면, 그 카드를 **덱 파일에서 뺀다**(사건 목록에 `absorbed`로 적고, 그 카드의 지문 중 쓸 만한 서술은 소유 카드의 해설에 옮긴다). 사용자 저장 데이터는 카드 id 기준이므로 빠진 카드의 상태는 **고아로 남고 로더가 모르는 id를 무시**한다(저장 호환, 진척 손실은 그 카드 한 장). 카드 파일에서 빠지는 것은 수정이 아니라 삭제라서 남은 카드의 `verified` 내용 해시(V14)는 변하지 않는다.
5. 사건 키는 한 번 정하면 바꾸지 않는다. 사건 이름(`title`)과 `note`는 자유롭게 고친다.

## 6. 현재 데이터 점검 (카드 84장, 연도로만 찾은 중복 후보)

연도가 같은 사료 카드를 찾았다. **같은 사건인지는 지문·해설을 읽어야 확정할 수 있고** 아래는 후보다. 소유 덱은 콘텐츠 세션이 정한다(제안은 규칙 1의 행위자 기준).

| 연도 | 카드 | 판단(제안) | 처리 후보 |
|---|---|---|---|
| 371 | 백제 `평양성 공격`(baekje-src-01) / 고구려 `고국원왕 전사`(goguryeo-src-05) | **같은 사건의 두 면**일 가능성이 높음(근초고왕의 평양성 공격과 고국원왕의 전사) | **관점 쌍 후보**(근초고왕 칸 vs 미천왕 칸이라는 서로 다른 칸을 묻는지 확인) 또는 한쪽으로 흡수 |
| 400 | 고구려 `신라 구원`(goguryeo-src-08) / 신라 `왜를 물리친 고구려 원군`(silla-src-02) | **같은 사건**(광개토왕의 신라 구원) | **소유 = 고구려**(행위자), 신라 카드는 해설로 흡수 |

- **가야 모델과의 연결**: 금관가야 병합(532)은 신라 덱에만 있다. 가야 사건이 각국 덱에 흡수될 때(D96) 사건 목록이 중복 흡수를 막는다.
- **영향**: 같은 사건 카드가 이미 약 3~4쌍이다. 지금 정리하지 않으면 M3에서 가야·남북국을 더할 때 중복이 늘어난다. 정리는 카드 삭제가 아니라 소유 덱 결정과 흡수다.

## 7. 수용 기준 (검증기 테스트)

1. 같은 `event_key`가 서로 다른 덱의 두 카드에 있으면 E3 오류(관점 쌍으로 등록된 쌍은 통과).
2. `event_key` 형식 위반, 사건 목록에 없는 키, `owner_card` 불일치, 연도 불일치가 각각 오류로 잡힌다(E2, E4~E6).
3. 관점 쌍 항목이 두 카드가 아니거나 같은 덱이면 오류(E7).
4. 같은 `year`이고 `exam_tags`가 겹치는 서로 다른 덱 카드 쌍이 `distinct_pairs`에 없으면 OBS로 나온다(오류 아님). `distinct_pairs`에 넣으면 사라진다.
5. 변형 검사(mutation): 정상 데이터에서 한 곳씩 망가뜨려(키 중복, 키 삭제, 연도 변경, 소유 카드 삭제) 모두 종료 코드 1이 된다. 정상 데이터는 0.
6. E1은 M3 전에는 경고, 옵션(`--strict-events`)을 주면 오류가 된다.

## 8. 열린 질문
- 관점 쌍을 몇 쌍까지 허용할지, 쌍의 두 카드를 같은 세션에 내지 않는 규칙을 웹이 어떻게 구현할지.
- `participants`를 카드 필드로 둘지(휴리스틱의 정확도를 높일 수 있음) 사건 목록에만 둘지.
- 한 사건에 대한 해설을 소유하지 않는 덱의 어느 카드에 둘지(링크 방식 vs 문장 복사).
- 전체 카드가 늘면(152장) 사건 목록을 사람이 어떻게 유지할지(콘텐츠 세션의 일이 늘어남).

# 지문 변형 명세 (카드당 지문 2~3개, 스키마 v2 확장 초안)

> **상태**: 초안(2026-11-05, D93·D162 제안 → D121) → **내용 경계 규칙 추가(D180: 같은 기사 안에서만, 해설·다른 카드·다른 사료 금지, 같은 덱 다른 카드 핵심어 금지; D131)**. 스키마 v2의 **하위 호환 확장**이다. 이 문서는 필드, 검증 규칙, 선택 규칙, 저장·로그, 도입 순서를 정한다. **콘텐츠 확대(고구려 36장 확인, 백제 등)보다 뒤**에 한다(D93).
> **근거**: M1 재평가(`docs/reviews/evaluation-m1.md` §2.2 "지문 암기"), M2 중간 평가 채택(D93: 세션 피로, 지문 변형은 스키마 확장 필요), `design/card-data-schema-v2.md`, `design/leitner-spec.md`.
> **한계**: 변형이 실제로 암기를 줄이는지는 검증하지 않았다(가설). 변형 지문 작성과 사실 확인 비용은 측정하지 않은 추정이다.

## 1. 문제와 목적

- 지문이 카드마다 하나로 고정이라, 같은 카드를 두세 번 만나면 **사건을 알아보는 것이 아니라 문구를 외워서** 답하게 된다(재평가 2.2 5번). 간격 반복의 목적(장면 인식 → 인출)이 약해진다.
- 카드당 **서로 다른 각도의 지문 2~3개**를 두고 카드를 다시 만날 때 돌려 보여 주면, 정답 칸·연도·해설은 그대로인데 지문 문구는 바뀐다.
- **하지 않는 것**: 정답이나 칸을 바꾸는 변형(변형은 같은 사건의 다른 서술이다), 기출 지문의 변형·복제(D79-4), 무한 생성(사람이 쓰고 확인한 2~3개만).

## 2. 스키마 변경 (하위 호환)

기존 `source_text`(+`text_basis`)는 그대로 **기본 지문(변형 1)**이다. 새 선택 필드 `variants`에 **추가 지문을 최대 2개** 둔다. `variants`가 없거나 비어 있으면 지금처럼 동작한다.

| 필드 | 타입 | 필수 | 설명 |
|---|---|---|---|
| `variants` | array | 아니오 | 추가 지문 목록(최대 2). 없으면 `[]`와 같다 |
| `variants[].id` | string | 예 | 카드 안에서 고유. `v2`, `v3` (기본 지문은 암묵적으로 `v1`) |
| `variants[].text` | string | 예 | 지문. `source_text`와 **같은 규칙**(§3의 V16) |
| `variants[].text_basis` | enum | 예 | `own_paraphrase_from_original`만 허용(번역문·기출 인용 금지) |
| `variants[].angle` | enum | 예 | 서술 각도: `record`(기록체 요약) / `actor`(인물·관직 시점) / `result`(결과·제도 시점) / `scene`(장면 묘사). 같은 카드 안에서 각도가 겹치지 않게 |
| `variants[].verification` | object | 예 | `verification`과 **같은 구조**(2인 확인, `content_hash`) |

```json
{
  "id": "goguryeo-src-09",
  "source_text": "왕이 도읍을 국내성에서 평양으로 옮겼다.",
  "text_basis": "own_paraphrase_from_original",
  "variants": [
    { "id": "v2", "angle": "record",
      "text": "왕이 도읍을 새로 정해 옮겼다는 짧은 기사다. 옮겨 간 곳은 평양이었다.",
      "text_basis": "own_paraphrase_from_original",
      "verification": { "verified": false, "verified_by": [], "verified_at": null, "original_checked": false, "exam_notation_checked": false, "content_hash": null } }
  ]
}
```
> 위 변형 문장은 **구조를 보여 주는 예시이며 사실 확인 전**이다. D180 이전 판의 예시("이후 나라의 힘이 남쪽으로 기울어졌다")는 기사에 없는 **해설의 결과 서술**이라 내용 경계(2.1절)에 어긋나 위와 같이 고쳤다(`record` 각도, 기사 한 줄 안의 내용만). 그 밖에 출발지 "국내성"처럼 원문이 아니라 통설로 확인한 사실도 기사에 없으면 변형에 쓰지 않는다.

- **같은 카드에서 바뀌지 않는 것**: `answer`, `year`, `clues`(단서는 카드 수준), `explanation`, `reign_label`, `source_ref`(출처는 카드 하나이므로 변형이 다른 출처를 쓰지 않는다. 쓰려면 별도 카드).
- `source_ref.note`에 변형 작성 메모를 적을 수 있다.

## 2.1 내용 경계 (D180, 변형 대조 결과)

**근거**: `design/fact-check-report-variants-m1.md` — 변형 12개 중 6개가 해설이나 다른 카드의 사실을 지문에 끌어왔고, 4개는 그 때문에 사실이 틀리거나(도교 "새 종교") 다른 카드와 구별이 안 됐다(서안평+관구검 침입, 진대법+을파소).

**규칙** (모두 변형 지문 `text`에 적용):
1. **같은 기사만**: 변형은 원 카드 `source_ref`가 가리키는 **같은 기사**(권·조)에 실린 내용만 쓴다. 같은 기사를 다른 각도로 풀어 쓰는 것이지 새 정보를 더하는 것이 아니다.
2. **금지**: ① **해설(`explanation`)에만 있는 내용**(배경, 이후의 영향, 학계 해석) ② **다른 카드의 사건·사실** ③ **다른 사료의 사실**(삼국유사·일본서기·비문·다른 본기·중국 사서 등 `source_ref`와 다른 출처). `result` 각도도 "기사가 직접 서술하는 결과"만 쓴다(해설의 의미 부여는 금지).
3. **같은 덱의 다른 카드의 핵심어 금지**: 같은 나라 덱의 다른 사료 카드의 **제목, 그 카드에만 나오는 사건명·인명·지명**을 변형에 쓰지 않는다. 이유: 두 카드를 같은 세션에서 만났을 때 한쪽이 다른 쪽의 정답을 알려 주거나 두 사건이 섞이지 않게 하기 위해서다.
4. 통설로만 확인한 사실(원문에 없는 출발지·위치 설명 등)도 기사에 없으면 변형에 쓰지 않는다(원 지문에 있더라도 변형은 기사 문장에 더 가깝게).

**검사** (자동은 보조이고 판단은 사람의 대조가 한다):

| # | 규칙 | 수준 |
|---|---|---|
| V22 | 변형 `text`가 **같은 나라 덱의 다른 사료 카드의 `title`**(3자 이상)을 포함하면 오류 | 오류 |
| V23 | 변형 `text`와 같은 카드 `explanation`이 **12자 이상 연속으로 겹치면** 관찰 줄을 낸다(해설 복제 의심) | OBS |
| V24 | 변형 `text`와 같은 덱 **다른 카드의 `source_text`**가 **10자 이상 연속으로 겹치면** 관찰 줄을 낸다(다른 카드 사실 의심) | OBS |
| (사람) | 위 규칙 1·2·3의 의미 검사: **변형 확인자는 변형을 원 기사와 비교해** 새 사실이 없는지, 다른 카드의 핵심어가 없는지 본다 | `design/human-review-guide.md` |

- **현재 데이터에서 잰 값**(제목·연도·주제로만 본 것, 구현 아님): 변형 24개 중 V22 해당 0건, V23 해당 2건(고구려 src-03 v2, 신라 src-08 v2, 13자), V24 해당 9쌍(변형 6개: 고구려 src-03·04·05·09·10의 v2, 백제 src-05의 v2). V24는 "평양성을 공격하였다" 같은 **흔한 구절**이 겹칠 수 있어 오탐이 많으므로 오류로 만들지 않고 사람 대조의 확인 목록으로만 쓴다.
- 검증기 구현(V22 오류, V23·V24 OBS)은 콘텐츠 세션 몫이다. 구현 전에는 사람 대조가 이 규칙을 지킨다.
- **R4와의 관계**: 이 규칙을 어긴 변형은 검증으로 걸러지지 않아도 사람 확인에서 `verified`가 되지 못하므로 런타임에서 건너뛴다.

## 3. 검증 규칙 (V16~V21, 내용 경계 V22~V24는 2.1절)

`tools/validate_cards_v2.py`의 V1~V15와 별개로 번호를 이어 붙인다(검증기 구현은 콘텐츠 세션 몫).

| # | 규칙 |
|---|---|
| V16 | 모든 변형 `text`가 V8과 같다: 카드 `title`, `answer.after` 앵커 제목, 연도 표현(`\d{3,4}\s*년`, `기원전`, `서기`)을 포함하지 않는다. 길이 20~200자(벗어나면 경고). **기본 지문과 다른 변형 사이에도 서로 같은 문장이 없어야 한다**(정규화한 문자열 비교, 같으면 오류) |
| V17 | 변형 `text_basis`가 `own_paraphrase_from_original`이다(V9와 같다). |
| V18 | 변형 개수가 0~2(기본 지문 포함 최대 3). `id`가 카드 안에서 고유하고 `v1`이 아니다. `angle`이 enum이고 같은 카드의 변형끼리 `angle`이 다르다 |
| V19 | 변형이 **다른 앵커 왕의 이름**을 포함하더라도(예: 이웃 왕) 허용하되 **관찰로 출력**한다(칸을 알려 줄 수 있다). 정답 칸의 이웃 왕 이름이 있으면 경고 |
| V20 | `variants[].verification`에 V14가 같이 적용된다(`verified`이면 2인, 원문·기출 표기 확인, `content_hash` 일치). `content_hash`는 변형 `text`와 `angle`을 포함해 계산한다 |
| V21 | 카드 `content_hash`는 기본 지문의 내용만 포함한다(변형의 추가·수정이 카드의 `verified`를 풀지 않는다. 변형은 각자 `verified`를 가진다) |

**release R4**: 출시 빌드는 `verified: true`이고 `disputed`가 아닌 변형만 싣는다. **확인되지 않은 변형은 런타임에서 건너뛴다**(그 카드는 확인된 지문만 돌려 보인다). 변형이 없거나 모두 미확인이면 기본 지문만 쓴다. 기본 지문이 미확인이면 카드 자체가 R1로 빠진다.

## 4. 선택 규칙 (런타임)

- **첫 노출은 항상 기본 지문(v1)**이다.
- 이후 노출에서는 **가장 오래 전에 보여 준(또는 한 번도 안 보여 준) 확인된 지문**을 고른다. 동률이면 `id` 순서. 같은 지문을 연속으로 보여 주지 않는다(지문이 둘 이상일 때).
- 선택은 **결정적**이다(저장 데이터와 카드로만 계산, 난수 없음): 같은 상태에서는 같은 지문.
- **세션 끝 재도전**: 가능하면 같은 세션에서 보여 준 지문과 **다른 지문**을 고른다(방금 해설을 읽은 직후라 문구가 아니라 장면 인식을 확인한다). 지문이 하나뿐이면 그대로. 재도전은 상자에 반영하지 않으므로(J7) 난이도 상승의 위험이 낮다. 재도전에서 보여 준 지문은 `variant_seen`에 세지 않는다(상태 불변).
- **사람 테스트(`?study=1`)**: 기존 M1 빌드는 변형이 없고 그대로 둔다. 이 확장을 쓰는 이후 테스트는 **사전 점검(pre)에 v1, 다음 날 재인출(post1)에 학습에서 보지 않은 변형**을 쓰는 설계가 가능하다(전이 측정). 별도 계획 문서에서 정한다.
- **연습(미리 복습·오답 노트)**: 같은 선택 규칙을 따르되 `variant_seen` 갱신은 하지 않는다(상태를 바꾸지 않는다, J6).

### 저장 데이터
`leitner-spec.md` §2의 카드 항목에 추가(없으면 기본값):
```json
"goguryeo-src-09": { "...": "...", "variant_last": "v2", "variant_seen": { "v1": 2, "v2": 1 } }
```
- `variant_last`: 마지막으로 보여 준 지문 id. `variant_seen`: 지문별 본 횟수(분석용).
- 지문이 바뀌거나 삭제되어 저장된 id가 없으면 기본 지문으로 돌아간다(저장 호환).

### 로그
`m1-plan.md` 로그 규격에 **`variant_id`**(`v1`/`v2`/`v3`)를 더한다. 기존 줄에는 없으면 `v1`로 읽는다.

## 5. 화면과 보상

- 지문 옆에 변형임을 알리는 표시는 두지 않는다(같은 카드의 다시 만남을 숨기려는 것이 아니라 정보가 학습에 쓸모없기 때문). 해설에는 "다른 지문으로도 만나게 됩니다" 같은 안내를 한 번만 둘 수 있다.
- 보상(`rewards-spec.md`)은 변형과 무관하다(XP와 보너스는 카드와 결과로만 계산).

## 6. 작성 가이드와 비용

- **각도**: `record`(사료의 서술 방식을 요약), `actor`(왕·신하·장수 중심), `result`(사건이 가져온 제도·영향 중심), `scene`(장면 묘사). 같은 사건이라도 핵심어가 겹치지 않게 쓴다.
- 지문마다 **정답 노출 위험**을 점검한다(`result` 각도가 해설을 앞질러 쓰는 경우, 특정 왕 이름을 그대로 쓰는 경우). 그리고 **2.1절 내용 경계**(같은 기사만, 해설·다른 카드·다른 사료 금지, 같은 덱 다른 카드 핵심어 금지)를 지킨다. `result`·`actor`는 해설의 의미 부여나 인물 설명이 들어오기 쉬워 특히 주의한다.
- **우선순위**: 기출 빈도 `상`·`중`이면서 (a) 기본 지문이 짧아(예: src-09 한 줄) 문구 암기가 쉬운 카드, (b) 핵심어가 정답을 노출하는 카드(살수대첩 등)부터 변형 1개를 먼저 만든다.
- **비용(측정하지 않은 추정)**: 변형 1개는 새 카드보다 짧지만 사실 확인(원문 대조, 2인)이 카드와 같은 절차를 따르므로 확인 시간이 변형 수에 거의 비례한다고 가정한다. 36장에 변형 1개씩이면 확인 대상이 36개 늘어난다. 인력이 병목이면 **새 카드 확장이 변형보다 우선**이다(D93).

## 7. 도입 순서

1. 이 명세 검토와 확정(이 문서).
2. 검증기 V16~V21, R4 구현(콘텐츠 세션).
3. 변형을 우선순위 카드 몇 장(예: 5~10장)에 시범 작성하고 2인 확인.
4. 웹이 선택 규칙·저장·로그를 구현(기존 저장과 호환).
5. 사람 테스트 설계(전이 측정)는 M1 결과 뒤.

## 8. 수용 기준 (단위 테스트)

1. `variants`가 없거나 비어 있으면 동작이 지금과 같다(회귀 없음).
2. 첫 노출은 v1이다.
3. 이후 노출은 가장 오래 안 본 확인된 지문이고 같은 지문을 연속으로 보이지 않는다(지문 2개 이상). 같은 상태에서 결과가 같다(결정성).
4. 미확인 변형은 선택되지 않는다. 모두 미확인이면 v1만 나온다.
5. 세션 끝 재도전은 가능하면 같은 세션에서 보인 지문과 다른 지문이다. 재도전·연습은 `variant_seen`을 바꾸지 않는다.
6. 저장된 `variant_last` id가 카드에서 사라졌으면 v1로 복귀한다.
7. 검증기: 변형 `text`가 제목·앵커 이름·연도를 포함하면 오류(V16), 변형끼리 문장이 같으면 오류, `angle` 중복 오류(V18), 변형 개수 3 초과 오류.
8. 카드 `content_hash`는 변형 수정에 영향받지 않는다(V21).
9. 로그에 `variant_id`가 기록되고 없으면 `v1`로 읽는다.
10. (V22) 변형 `text`가 같은 덱 다른 카드의 `title`(3자 이상)을 포함하면 오류, 다른 덱 카드의 제목은 해당 없음.
11. (V23·V24) 해설과 12자 이상, 같은 덱 다른 카드 지문과 10자 이상 연속으로 겹치면 오류가 아니라 관찰 줄이 나온다.
12. 변형 확인 항목은 `card_id#vN`으로 기록되고(`tools/mark_verified.py`), 변형 내용이 바뀌면 변형 해시가 달라져 이전 확인이 무효가 된다(V20).

## 9. 판단 기록

| # | 판단 | 이유 | 확인할 것 |
|---|---|---|---|
| C1 | 기본 지문 `source_text`를 그대로 두고 `variants`를 추가 | 하위 호환, 기존 데이터·검증기·M1 빌드가 깨지지 않음 | 파일이 커지는 점 |
| C2 | 변형마다 독립 `verification` | 변형은 새 문장이라 새 사실 오류의 위험. 카드 확인과 분리하면 변형이 늦어도 카드는 출시 가능 | 확인 비용의 증가 |
| C3 | 확인되지 않은 변형은 런타임에서 건너뜀 | 품질 게이트(D56)를 우회하지 않으면서 점진 도입 | 미확인 변형이 많으면 효과 없음 |
| C4 | 선택은 결정적(가장 오래 안 본 지문) | 테스트 가능, 사용자가 같은 지문만 반복해 만나지 않게 | 지문 수가 적으면 순환이 짧음 |
| C5 | 재도전은 다른 지문 | 방금 읽은 문구가 아니라 장면 인식 확인 | 재도전이 너무 어려워지는지(M1 관찰 J7) |
| C6 | 변형은 카드당 최대 2개(총 3) | 작성·확인 비용 제한, 효과 체감 감소 | 1개로도 충분한지 |
| C7 | 변형은 원 기사 범위 안에서만, 해설·다른 카드·다른 사료·같은 덱 다른 카드 핵심어 금지 (D180) | 변형 대조에서 12개 중 6개가 해설·다른 카드 사실을 끌어와 사실 오류와 카드 혼동이 생겼다. 변형을 같은 기사의 재서술로 한정하면 사실 확인이 기사 하나 대조로 끝나고 변형 간 혼동이 준다 | 이 제약이 `result` 각도를 너무 얇게 만드는지, V24 오탐률 |

## 10. 열린 질문
- 변형이 암기를 줄이는지(다음 날 재인출을 변형 지문으로 측정하는 실험).
- 변형 작성을 자동으로 도울 수 있는지(모델이 초안을 쓰고 사람이 확인): 사실 오류 위험 때문에 도입 시 별도 게이트.
- 해설에도 변형이 필요한지(지금은 카드 하나의 해설).
- 지문을 두 개 이상 한 번에 보여 주는 문항 변형(M2 범위 밖, 스키마 v2 "아직 정하지 않은 것").

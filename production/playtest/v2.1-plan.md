# v2.1 플레이테스트 계획

> **작성**: 2026-11-04 (위임 규칙에 따라 사용자 질문 없이 보수적 기본값으로 작성)
> **빌드**: `web/` 웹 플레이 빌드. 실행: `web/README.md`. 실행한 커밋 해시를 보고서에 적는다.
> **관련 결정**: `docs/decision-log.md` D1(조건), D2(시기 정의), D3(조사 확인 사항), D22(소거 없이 추리), D27(유형 배지)
> **결과 기록 양식**: `production/playtest/v2.1-report-template.md`

## 1. 목표

이번 플레이테스트는 아래 질문에 답하려는 것이다. 표본이 작아서 통계적 결론이 아니라 방향 판단이다.

| ID | 질문 | 근거 | 확인 방법 |
|---|---|---|---|
| G1 | 시기 정의(건국기·전성기·결말기)가 헷갈리지 않는가 | D1 조건, D2 | 사후 질문 1, 관찰(열 머리글을 읽는지, 멈추는 카드) |
| G2 | 플레이어가 놓은 칸의 **근거를 말할 수 있는가** | D3(조사 확인 사항 1) | 사후 질문 2, 소리 내어 말하기 |
| G3 | 소거(남은 칸으로 푸는 것) 없이 추리로 푸는가 | D22 | 사후 질문 3, 라운드 앞쪽·뒤쪽 정답률 비교 |
| G4 | 외부 테스터에게도 암기 퀴즈가 아니라 추리로 느껴지는가 | v2 가설(D1) | 사후 질문 4, 단서 단계 분포 |
| G5 | 카드 유형 배지(예: "전승")를 정답 단서로 쓰는가 | D27 | 관찰(배지를 언급하는지), 사후 질문 3 |

## 2. 참가자

- **사용자 본인 1회**: 이미 v1·v2를 해 본 내부 플레이어. 추리 감각과 기록 JSON 확인용이다. 외부 테스터와 점수를 섞지 않고 따로 적는다.
- **외부 테스터 1~3명**: 한국사를 잘 모르는 사람. 시작 전 한 문장으로 자기 평가를 묻는다("삼국시대를 얼마나 아는가, 1~5"). 가능하면 1~2점인 사람을 우선한다. 개발에 관여한 사람은 제외한다.
- 테스터 ID는 `T1`, `T2`...로 붙이고 이름은 기록하지 않는다. 사용자 본인은 `U`.

## 3. 준비

1. 저장소 루트에서 `python3 -m http.server 8000` 후 http://localhost:8000/web/ 을 연다(`file://`로는 카드 JSON을 읽지 못한다).
2. **테스터마다 깨끗한 브라우저 상태로 시작한다.** 기록과 도감이 브라우저 localStorage에 쌓이므로(`web/README.md`) 새 시크릿 창을 쓰거나 저장소를 지우고 시작한다. 그렇지 않으면 앞사람의 기록이 섞인다.
3. 하단 바에서 `samguk.json`, 판정 카드 36장, 기준 카드 4장이 보이는지 확인한다. 검증 오류 목록이 뜨면 시작하지 않는다.
4. 외부 테스터에게 보여 줄 환경은 사용자가 정한다. 이 계획은 사용자의 PC에서 옆에 앉아 진행하는 방식을 기본으로 한다. 정적 호스팅은 이 세션에서 하지 않았고 정하지도 않았다.
5. 화면 녹화 여부는 테스터 동의를 받은 경우에만 한다. 동의가 없으면 메모만 한다.
6. 카드 사실 확인이 되지 않았다(`verified: false`). 하단 바에 "사실 확인 전"이라고 표시되어 있으므로, 테스터에게 "역사 내용은 검증 전의 초안"이라고 알린다.

## 4. 진행 대본

**진행자가 말하는 것은 아래 설명 1회뿐이다. 시작한 뒤에는 개입하지 않는다.**

> "이 게임은 이름이 숨겨진 사건 카드를 읽고, 오른쪽 보드에서 나라와 시기가 맞는 칸에 놓는 게임입니다. 모르면 '단서 더 보기'를 눌러 힌트를 더 볼 수 있어요. 틀려도 해설이 나옵니다. 생각나는 것을 소리 내어 말해 주세요. 제가 질문에 대답하지 못할 수도 있습니다. 시작하겠습니다."

개입 금지 규칙:
- 시작 후 도움, 힌트, 설명, 정답 확인을 하지 않는다. 튜토리얼은 게임이 자동으로 보여 준다.
- 막혀서 멈춰도 개입하지 않는다. 5분 이상 진전이 없고 테스터가 직접 도움을 청하면 그 사실을 메모하고 "다음 카드로 가 보세요" 정도만 말한다.
- 질문을 받으면 "나중에 알려 드릴게요"라고만 한다.
- 버그로 화면이 멈추면 개입하고 보고서의 Bugs 표에 기록한다.
- 소리 내어 말하기를 안 하면 "지금 무슨 생각이 드세요?"를 라운드당 최대 2번만 묻는다.

진행 순서와 시간(시간은 추정이 아니라 이번에 측정할 값이다):
1. 사전 질문 1개(자기 평가 1~5)
2. 설명 1회
3. 튜토리얼(자동) → 라운드 1회(12장)
4. 라운드 결과 화면 확인 → 라운드 2회(12장)
5. 도감 열어 보기(자유롭게 1~2분)
6. 사후 질문 5개
7. 기록 내보내기(JSON) 후 저장
- 중단 조건: 라운드 2회를 마치거나 시작 후 30분이 지나면 끝낸다. 먹물이 소진되어 실패하면 같은 라운드를 다시 하는 것이 아니라 다음 라운드로 넘어가도록 하고, 실패 횟수를 기록한다.

## 6. 사후 질문 (순서대로 한 번에 하나씩)

1. "시기(건국기, 전성기, 결말기)를 고르다가 헷갈린 카드가 있었나요? 각 시기를 어떤 기준이라고 이해하셨어요?" (G1)
2. "마지막으로 놓은 카드 하나를 골라서, 왜 그 칸에 놓았는지 말해 주세요." (G2: 답을 아래 3단계로 채점한다)
3. "정답을 고를 때 주로 어떻게 했어요? 아는 것, 단서로 좁히기, 남은 칸 보기, 찍기 중에서요." (G3, G5. 유도하지 않고 먼저 자유롭게 답하게 한 뒤 보기를 읽어 준다)
4. "퀴즈와 비슷했나요, 달랐나요? 한 번 더 하고 싶은가요, 그 이유는요?" (G4)
5. "무엇이 가장 헷갈렸나요?" (한 가지만. 프로토콜의 단일 질문)

질문 2의 채점(진행자가 아니라 기록 후 분석 시점에 매긴다):
- **2점**: 단서 내용 + 기준 카드나 시기 정의와의 관계를 말한다.
- **1점**: 단서 내용만 말한다("~라고 해서").
- **0점**: 말하지 못한다("그냥", "찍었어요").

## 7. 수집할 수치

### 웹 기록 JSON(`기록 내보내기 (JSON)`)에서
형식: `format: "hanyang-dogam-playlog"`, `history[]`에 라운드별 `levels`와 `placements[{id, correct, level}]`. 카드 id만 담기고 개인 정보는 없다(`web/README.md`).

| 지표 | 계산 |
|---|---|
| 정답률 | 정답 placements / 전체 placements (튜토리얼은 기록에서 제외됨) |
| 단서 단계 분포 | `level` 1/2/3의 비율 |
| 단서를 더 본 카드 비율 | `level` ≥ 2인 placements / 전체 |
| 1단계에서 정답 비율 | `level` = 1이고 정답 / `level` = 1 전체 |
| 라운드별 앞/뒤 정답률 | 한 라운드의 1~6번째와 7~12번째 placements 비교(G3: 뒤쪽이 눈에 띄게 높으면 소거 의심) |
| 오답이 많은 카드 | 오답 카드 `id`별 횟수(카드 설계 점검) |

### JSON에 없는 것 → 진행자가 직접 기록
JSON에는 내보낸 시각(`exportedAt`), 튜토리얼 완료/건너뜀(`tutorial`), 수집·오답 공개 카드(`collection`), 집계(`stats`)가 있다(`web/src/main.js`의 `exportPlayLog`). **카드별·라운드별 소요 시간과 테스터 ID는 없다.** 따라서 **테스터마다 내보낸 파일을 `playlog-<테스터ID>.json`으로 이름을 바꿔 저장**하고, 시작·종료 시각, 소요 시간, 도움 요청 횟수, 자기 평가 점수는 보고서에 손으로 적는다. 라운드 결과(클리어/실패)는 `history[]`에서 읽을 수 있는지 확인하고, 읽을 수 없으면 손으로 적는다.

## 8. 판단 기준 (PROCEED / PIVOT)

표본이 1~4명이므로 한 사람의 극단적인 결과로 판정하지 않고, 수치와 관찰을 함께 본다. 표의 기준은 v2 가설(정답률 40~70%, 절반 이상의 카드에서 단서 더 보기)과 D1, D3, D22에서 가져왔다.

**PROCEED(시기 정의 D2와 v2 규칙을 확정하고 콘텐츠 검증·구현을 계속)** — 아래를 모두 만족:
1. 외부 테스터의 정답률 평균이 40~70%
2. 질문 2 채점 평균이 1.0 이상(절반 이상이 근거를 말할 수 있다)
3. 질문 1에서 "시기 구분이 헷갈렸다"고 답한 외부 테스터가 과반 미만이고, 헷갈린 카드가 한두 장에 몰린다면 그 카드만 고친다
4. 소거나 유형 배지에 의존한다는 증거가 약하다(질문 3·관찰에서 소거/배지가 주된 방법이 아님, 라운드 뒤쪽 정답률이 앞쪽보다 눈에 띄게 높지 않음)

**PIVOT(해당하는 부분만 고쳐 v2.2를 다시 테스트)** — 하나라도 해당:
| 신호 | 진단 | 고칠 부분 |
|---|---|---|
| 정답률 70% 초과이면서 단서를 더 본 카드 30% 미만 | 너무 쉽다(암기 또는 배지 의존) | 유형 배지 숨김(D27), 단서 재설계 |
| 정답률 40% 미만 | 너무 어렵거나 시기 정의가 불명확하다 | 시기 정의 표기(연대 보조 표시 등), 단서 3단계 보강 |
| 시기 구분이 헷갈렸다는 외부 테스터가 과반 | 시기 축 개념 자체가 불명확하다 | D2 재검토(라벨, 정의 문구, 축 구조) |
| 질문 2 채점 평균이 1.0 미만 | 추리가 아니라 찍기 | 관계 단서의 역할 재설계 |
| 뒤쪽 정답률이 앞쪽보다 눈에 띄게 높음 | 소거 풀이 | 라운드 카드 구성(D22) 재검토 |

**KILL 검토 신호**: 외부 테스터 모두에게서 "한 번 더 하고 싶은가"에 부정적이고 재미 신호(웃음, "아!", 다시 하자는 말)가 한 번도 없을 때. 그 경우에는 숫자와 상관없이 컨셉 판단 단계로 돌아가 사용자에게 보고한다.

**NOT ASSESSED**: 외부 테스터가 한 명도 없거나 기록 JSON을 얻지 못하면 PROCEED/PIVOT 판정을 하지 않고 "사용자 1명의 소감"으로만 기록한다.

## 9. 알려진 한계

- 표본이 매우 작다. 위 기준은 방향을 보기 위한 가이드이며 통계적 근거가 아니다.
- 카드 44장 전부 `verified: false`이다. 역사 내용의 정확성은 이 플레이테스트에서 검증하지 않는다.
- 웹 빌드는 `image` 필드를 그리지 않는다. 일러스트와 대체 문양이 없는 상태에서의 인상이며, 아트 방향은 평가 대상이 아니다.
- Godot 빌드는 이 플레이테스트에 쓰지 않는다. 클라우드 세션에서 실행해 본 적이 없다.
- 유형 배지가 정답 단서가 될 수 있다(D27). 이번 테스트에서는 현재 상태 그대로 두고 관찰하는 것이 G5의 목적이다. 먼저 배지를 숨기고 테스트하려면 이 계획을 고쳐야 한다.

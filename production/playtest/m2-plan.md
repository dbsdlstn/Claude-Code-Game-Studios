# M2 사람 테스트 계획: 타이틀·보상·도감이 학습 행동을 해치지 않는가

> **상태**: 초안(2026-11-05, D130). `production/milestones/m2.md` 4절의 T1~T9를 실제 진행 절차로 옮긴 것이다. 형식은 `production/playtest/m1-plan.md`와 `prototypes/m1-timeline/STUDY.md`를 따랐다.
> **M1 비교 테스트와 다른 점**: M1은 연표 방식 대 플래시카드 **방식 비교**(`?study=1`, 보상 꺼짐)였다. M2는 **일반 모드**(타이틀·보상·도감 켜짐)를 며칠 쓰게 하고 **사용성과 보상 행동**을 본다. 방식 비교가 아니다.
> **한계**: 참가자 1~2명, 며칠 사용, 모델이 만든 임계값(m2.md가 정한 초기값)이다. 통계적 결론이 아니라 방향 판단이다. 로그에 쓰는 일부 이벤트는 현재 웹에 **없다**(8절 요청 목록).

## 1. 무엇을 알아보는가

1. 앱을 열고 첫 카드까지 빨리 가는가, 복귀하는 날은 더 빨리 가는가 (T1)
2. 보상이 **학습과 같은 방향**임을 사용자가 이해하는가 (T2)
3. 보상이 **단서 사용을 왜곡**하지 않는가 (T3), 보상을 의식한 **이상 행동**이 있는가 (T4)
4. 세션 길이와 **지문 암기 피로** (T5)
5. 도감(카드·업적·칭호·오답 노트)을 **이해하고 쓰는가** (T6)
6. **다음 날 다시 오고 싶은가**, 이유가 학습인가 보상인가 (T7)
7. 나라를 바꿀 때 진행 중 세션 손실 문제 (T8)
8. 모바일 접근성·사용성 (T9)

## 3. 참가자와 진행

- **인원**: 1~2명. 각자 따로 판정한다. 한 명이면 한계를 보고서에 적는다.
- **기간**: **3~5일**(권장 4일). 하루 한 세션을 목표로 권하되 **의무가 아니다**(쉬는 날이 생기는지도 본다).
- **기기**: 참가자의 **자기 휴대폰**(세로). 같은 기기·같은 브라우저를 끝까지 쓴다. 사생활 보호 창은 쓰지 않는다. 브라우저 데이터를 지우지 않는다.
- **참가자 ID**: `P1`, `P2`. 도감 안의 "참가자 ID" 칸에 입력한다(진행자가 Day 0에 입력해 준다).
- **이름 같은 개인정보는 적지 않는다.** 로그에는 ID와 학습 기록만 남는다. 녹화는 동의 시에만.

## 4. Day 0 진행 (대본과 순서)

설명은 **1회**만 한다. 첫 화면을 열기 **전에** 읽는다.

> **고지(해당 시)**: "카드의 내용은 아직 검증 전 초안이라 시험 대비용 사실로 외우시면 안 됩니다. 끝나면 정정할 부분을 알려 드립니다."
> **목적**: "이 앱을 며칠 써 보시면서 불편한 점과 좋았던 점을 알아보려는 거예요. 점수를 매기는 시험이 아니고, 모르면 모른다고 하셔도 됩니다. 생각나는 것을 소리 내어 말해 주세요."
> **개입 금지**: "처음에는 설명 없이 직접 해 보세요. 막히면 어떻게 하시는지가 중요해서, 도움은 나중에 드립니다."

| 단계 | 내용 | 관찰·기록 |
|---|---|---|
| 1 | 사전 질문(한능검 경험, 하루 공부 시간, 평소 쓰는 앱) | 응답 |
| 2 | **첫 실행**: 주소를 열게 하고 첫 카드가 나올 때까지 지켜본다 | **T1**: 시간(초시계), 누른 횟수, 헤맨 곳, 안내(온보딩) 건너뜀 여부 |
| 3 | 세션 1 (끝까지) | 소리 내어 말한 것, 단서를 여는 시점·이유, 표정/한숨 |
| 4 | 결과 화면에서 **아무것도 하지 말고 화면을 보게 한다**(말없이 지켜본다) | 결과 화면에 머문 시간, 화면을 탭했는지, 전체 보기를 열었는지 |
| 5 | 세션 2 (끝까지) | 세션 1과 같음. **상한 안내(하루 24장)가 이 시점에 보이는지** 확인 |
| 6 | **보상 이해 질문(T2)**: ① "경험치가 언제 더 오르나요?" ② "단서를 보면 어떻게 되나요?" ③ "레벨이 오르면 뭐가 달라지나요?" | 응답 원문(코딩은 7절) |
| 7 | **도감 과제(T6)**: ① "은 등급 카드를 찾아 보세요" ② "아직 못 받은 업적 하나를 말해 보세요" ③ "칭호를 바꿔 보세요" ④ "오답 노트에서 한 장 연습해 보세요" | 과제별 성공/실패, 시간, 헤맨 곳 |
| 8 | 마무리: 기록 내보내기를 한 번 해 본다(내보내기 위치를 알게) | 위치를 찾았는지 |

## 5. 마지막 날 진행

1. **기록 내보내기**: 참가자 기기에서 "도감 → 기록 내보내기"로 `.jsonl`을 받는다(진행자에게 전달: 메신저/메일). 받은 파일은 **저장소 밖의 안전한 폴더**에 `m2-<ID>.jsonl`로 보관한다(날 데이터는 저장소에 커밋하지 않는다).
2. **나라 전환 과제(T8)**: 나라가 둘 이상 활성이면, 세션 중간에 "다른 나라로 바꿔 보세요"를 시킨다. 확인 대화상자가 뜨는지, 진행 중 세션이 어떻게 되는지 보고 불만을 묻는다.
3. **사후 인터뷰(T7, T4, T5)**: 10절 질문을 한 번에 하나씩.
4. **정답·정정 안내**: 카드 내용에 정정이 있으면 이때 알린다.
5. 참가자 기록은 요청이 없으면 그대로 두고, 요청하면 "학습 기록 초기화"(두 번 확인)로 지운다.

- **M2 PASS**: T3·T4·T9에 문제가 없고, 나머지 7개 중 5개 이상 기준 충족.

## 7b. D167 분석: 첫 만남 결과별 다음 만남 정답률, 단서를 처음 연 시점

> D167(디렉터 채택, D187)에서 추가. **새 로그 필드는 필요 없다.** D108이 넣은 인출 줄 필드(`card_id`, `correct`, `clue_used`, `practice`, `ts_ms`, `box_before`, `clue_open_ms`)만으로 계산한다. 참가자 1~2명이므로 아래 값은 **방향을 보는 관찰값**이고 통계 검정을 하지 않는다. 같은 카드를 다시 만나는 간격은 학습 일정이 정하므로 "단서가 학습을 낳았다"는 인과가 아니라 **연관**으로만 적는다.

### A. 첫 만남 결과별 다음 만남 정답률
1. **대상 줄**: `practice`가 아닌 `learn` 줄(연습은 제외, 같은 날 재도전은 `reason`이 없으므로 `ts_ms`로 같은 세션 안 두 번째 줄을 제외하고 **세션당 카드별 첫 줄**만 쓴다).
2. **첫 만남**: 참가자·카드 기준으로 `ts_ms`가 가장 이른 대상 줄.
3. **첫 만남 결과 3분류**(T3과 같은 정의): ① **깨끗** = `correct`이고 `clue_used` 0 ② **단서** = `correct`이고 `clue_used` ≥ 1(직접/관계는 T3과 같은 규칙으로 나눠도 좋다) ③ **오답** = `correct`가 아님.
4. **다음 만남**: 같은 카드의 그다음 대상 줄(다른 세션, 즉 다른 `session_start` 구간). 다음 만남이 없는 카드(기간 안에 다시 안 나옴)는 분모에서 빼고 개수를 따로 적는다.
5. **지표**: 분류별 `(다음 만남 깨끗 정답 수 / 분류 카드 수)`와 `(다음 만남 정답 수 / 분류 카드 수)` 두 가지. 표본이 작으니 **분모(카드 수)를 항상 같이 적는다**. 분모 5장 미만인 칸은 "표본 부족"으로 쓰고 비율은 쓰지 않는다.
6. **기대하는 방향(가설, 틀릴 수 있음)**: 깨끗 > 단서 > 오답 순으로 다음 정답률이 높다. 단서와 오답의 차이가 작거나 뒤집히면 "단서를 쓰는 것이 학습에 도움이 안 된다" 또는 "일정 간격이 달랐다" 둘 다 가능하므로 `box_before`와 간격(일 수)을 같이 본다.
7. **보상과의 연결**: 단서를 써도 보상 XP가 5/3으로 깎일 뿐 승급은 되는데(rewards-spec), 단서 카드의 다음 정답률이 오답 카드와 비슷하면 보상 설계(단서 사용 허용 폭)를 다시 볼 근거가 된다. 이 판단은 **디렉터** 몫이다.

### B. 단서를 처음 열기까지 시간
1. **자료**: `learn` 줄의 `clue_open_ms`(카드가 보인 뒤 처음 단서를 연 시점, 안 열었으면 null).
2. **지표**: 단서를 연 인출만 대상으로 참가자별 `clue_open_ms`의 **중앙값과 사분위(25·75%)**, 그리고 `box_before`별(새 카드 / 1 / 2 이상) 중앙값. 단서를 열지 않은 인출은 비율로만 적는다(T3의 사용률과 같은 값).
3. **해석 가이드**: 매우 짧으면(예: 카드가 보이고 바로 연다) "생각해 보기 전에 단서부터 본다"일 수 있고, 길면 먼저 시도한 뒤 연다. 기준값을 미리 정하지 않는다(M1 사람 데이터 없음). **인터뷰 질문 "단서를 언제 열어요?"와 함께** 본다(10절).
4. **상호작용**: `clue_open_ms`와 `ms_on_card`의 차이(단서를 연 뒤 걸린 시간)도 함께 적는다.

- 계산은 내보낸 JSONL을 읽는 스크래치 스크립트로 한다(저장소에 넣지 않아도 되지만, 보고서에 **계산 정의 3줄**(대상 줄·첫 만남·다음 만남)을 적는다).
- 세션 도중 닫힌 세션(`session_end.reason = closed`)은 포함하되 개수를 적는다.

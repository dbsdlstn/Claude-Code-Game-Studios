# 마일스톤 M2: 타이틀·보상·고구려 36장 (학습 모드 본 구현)

> **상태**: 완료 조건 초안(2026-11-05, D123). M2의 정의는 `docs/roadmap.md` M2와 D79다. 이 문서는 **무엇이 되면 M2가 끝인지**, **어떤 증거로 확인하는지**, **사람 테스트에서 무엇을 보는지**를 정한다.
> **근거**: D79(사용자 피드백), D93·D94(중간 평가 채택), D120~D122, `design/rewards-spec.md`, `design/ux/title-screen.md`·`session-result.md`·`dogam.md`, `design/content-plan-m2.md`, `design/card-variants-spec.md`, `design/leitner-spec.md`.
> **이 문서의 한계**: 구현 상태는 이 세션이 실행해서 확인한 것이 아니다. "현재" 열은 결정 기록과 파일 목록으로 안 사실만 적었고 `확인 못 함`은 직접 확인하지 못한 항목이다. 수치 기준(통과 임계값)은 이 문서가 임의로 정한 초기값이며 총괄과 사용자가 바꿀 수 있다.

## 1. 두 단계 게이트

M2는 **개발 완료(M2-A)**와 **출시 준비(M2-B)**로 나눈다. 개발은 사람 확인 없이 끝낼 수 있고, 출시는 사람이 필요하다.

| 게이트 | 뜻 | 누가 | 막는 것 |
|---|---|---|---|
| **M2-A 개발 완료** | 기능, 명세 일치, 자동 테스트, 화면 증거, 콘텐츠 초안이 갖춰짐 | 모델 세션(웹·콘텐츠·설계) | 다음 마일스톤 착수 |
| **M2-B 출시 준비** | 사실 확인, 사람 테스트, 모바일 실기기 확인이 끝남 | 사람(확인자, 수험생, 사용자) | 수험생에게 내보내기 |

> M3(백제·신라·가야)는 **M2-A가 끝나면 시작해도 된다**(콘텐츠는 병렬). 수험생에게 내보내는 것은 M2-B가 끝나야 한다.

## 4. M2 사람 테스트 (M1 비교 테스트와 별개)

**목적**: 타이틀·보상·도감이 **학습 행동을 해치지 않고** 다시 오고 싶게 만드는지 본다. M1(연표 vs 플래시카드)과 달리 **방식 비교가 아니라 사용성과 보상 행동 관찰**이다. 참가자는 수험생 1~3명(M1 참가자와 같아도 되지만 이미 아는 사람은 첫 실행 관찰이 어렵다).

**방법(제안)**: 일반 모드(`?study` 없음)로 Day 0 약 30분(첫 실행 → 세션 2회 → 도감), Day 1~2에 자유 사용 후 인터뷰 10분. 진행자는 M1 대본과 같은 원칙(설명 1회, 도움 금지).

### 4.1 관찰·측정 항목
| # | 항목 | 기록 | 통과 기준(초기값) |
|---|---|---|---|
| T1 | **첫 세션까지**: 앱 열기부터 첫 카드까지 탭 수와 시간 | 진행자 관찰, 로그 | 복귀 시 탭 1~2번, 첫 실행 안내 포함 60초 이내 |
| T2 | **보상 이해**: "경험치가 언제 더 오르나요?"를 말로 설명 | 응답 | 참가자 중 절반 이상이 "힌트 없이 맞히면 더 오른다"를 설명 |
| T3 | **단서 행동**: 보상이 단서 사용을 막거나 부추기는가. 상자 2 이상 카드의 `clue_used` 분포를 M1(보상 없음)과 비교 | 로그 | 직접 단서 사용률이 M1 대비 **급감하거나 폭증하지 않음**(±15%p 안, 초기값). 모를 때 단서를 쓰는 행동이 사라지면 PIVOT |
| T4 | **보상 vs 학습**: 보상을 의식해 정답 대신 쉬운 카드/찍기를 고르는 행동이 있나 | 관찰·인터뷰 | 그런 행동이 보이면 기록, 2명 이상이면 `rewards.json` 조정 |
| T5 | **세션 길이·피로**: 세션 5~10분이 맞는지, 36장 덱에서 같은 지문을 반복해 외우는 느낌 | 시간 측정, 질문 | 세션 중앙값 5~10분. "지문을 외운다"는 응답이 절반 넘으면 지문 변형 우선순위 상향 |
| T6 | **도감 이해**: 아직 안 만난 카드가 가려진 것, 등급, 업적을 이해 | 과제("은 등급 카드를 찾아 보세요") | 과제 성공률 80% 이상 |
| T7 | **복귀 의사**: 내일도 하고 싶은가, 이유가 보상인가 학습인가 | 인터뷰 1~5점 | 평균 3.5 이상(초기값), 이유에 "학습/진척"이 언급됨 |
| T8 | **나라 선택**: 나라를 바꾸는 상황에서 진행 중 세션이 사라지는 불만 | 관찰 | 불만 없음 또는 확인 대화상자로 해소 |
| T9 | **접근성·모바일**: 가로 스크롤, 터치 실패, 글자 크기 | 관찰 | 0건 |

### 4.2 판정
- **M2 PASS**: T1~T9 중 T3·T4·T9가 문제 없고 나머지 7개 중 5개 이상이 기준을 충족.
- **M2 PIVOT**: T3(보상이 단서 행동을 왜곡) 또는 T4(보상 최적화 행동 2명 이상) → `rewards.json` 수치/보상 구조를 고치고 재테스트.
- **NOT ASSESSED**: 참가자 0명, 또는 카드 확인(B1) 없이 사실 오류가 발견된 채 정정 전.
- 결과 해석의 한계: 참가자 1~3명, 모델 에이전트의 사전 평가는 인간 정답이 아님.

## 5. 되돌림 조건과 위험

| 상황 | 대응 |
|---|---|
| M1 판정이 PIVOT/차이 없음/KILL | M2에서 스키마·Leitner 확정을 보류하고 총괄이 어디를 되돌릴지 정한다(타이틀·보상은 학습 방식과 독립이라 유지 가능, 연표 의존 부분은 재검토) |
| 보상이 단서 행동을 왜곡(T3) | 해당 보상을 끄거나 수치 조정, `rewards.json`만 바꿈 |
| 구현 비용이 계획의 2배 초과 | 범위를 줄여 총괄에 올림(도감 탭, 업적 일부, 같은 날 재출제 금지 순으로 후순위) |
| 사실 확인 인력 부족 | 카드 수보다 확인 인력을 먼저 해결, 확인 전 카드는 release에서 제외 |
| 덱 확대로 용량 초과 | 백로그 보호 + 나라별 독립 덱(F6) |

## 6. M2 종료 절차
1. M2-A 체크리스트(2절) 전부 증거 링크와 함께 확인 → 결정 기록 정리(D5) → M3 착수 승인.
2. M2-B(3절)가 끝나면 사람 테스트(4절) 결과를 `production/playtest/`에 보고서로 남기고 PASS/PIVOT를 총괄이 승인.
3. 스키마 v2와 Leitner 명세의 **최종 확정**은 M1 판정(PROCEED)과 M2 결과를 함께 본 뒤 총괄이 한다.

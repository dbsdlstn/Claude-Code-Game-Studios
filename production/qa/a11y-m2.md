> 웹 빌드 세션, 2026-11-05, 결정 기록 D110. 대상은 `prototypes/m1-timeline/`의 일반 학습 모드다. 사람 테스트 모드(`?study=1`)는 M1 점검(D75)을 따르고 이번에 바꾸지 않았다.
> **자동 점검**은 e2e(`tests/e2e-m2.test.mjs` "접근성" 테스트, 도우미 `tests/a11y.mjs`)로 매번 다시 돈다. **사람만 할 수 있는 점검**(실제 스크린리더, 실기기)은 M2-B 몫이고 아래에 "미확인"으로 적었다.

## 2. 사람이 확인해야 하는 것 (미확인, M2-B)

- 실제 스크린리더(iOS VoiceOver, Android TalkBack)로 학습 한 세션: 칸 버튼 이름("○○ 즉위 이후 ~ ○○ 즉위 이전 칸에 꽂기")이 길어 듣기 불편한지, 결과 낭독 문장의 순서.
- 글자 확대 200%에서 연표 한 줄(재위 기간 + 왕 이름 + "+")이 겹치지 않는지.
- 다크 테마: 아직 없다(art-bible §4.4 규칙이 있으나 웹은 라이트만).
- 실기기에서 연표 경계 "+"(44px, 앵커 경계에 걸침)를 엄지로 누를 때 옆 줄을 잘못 누르는지.
- 결과 화면 자동 등장(0.35초 간격)이 전정 장애가 있는 사람에게 불편한지(`prefers-reduced-motion`을 켜면 정적).

## 3. 알려진 한계

- 대비 계산은 배경 이미지(한지 무늬 그라데이션)를 무시하고 바탕색만 본다. 무늬가 옅어(투명도 0.03~0.45) 실제 대비는 계산값과 거의 같다고 보지만 측정하지 않았다.
- `disabled` 요소("준비 중" 나라, 비활성 버튼)는 WCAG 대비 예외라 점검에서 뺐다.

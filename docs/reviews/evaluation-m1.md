## 2. 새로 생긴 문제

### 2.1 재미·정체성
- **"추리형 퍼즐"은 이름만 남았다.** 기준 카드에 왕 이름과 재위가 적혀 있다. 12장 중 11장은 "그 왕 이름 바로 아래 칸"이 정답이다. 그래서 동작이 "사건을 알아보고 → 왕을 떠올리고 → 목록에서 찾기"가 된다. 진짜 추론이 필요한 카드는 고국원왕 전사(05, 기준 카드가 없는 왕) 정도이고, 넓게 잡아도 2~3장이다(CD·GD 일치).
- 두 평가자 모두 이것을 **학습 도구로서는 결함이 아니라고** 본다. 다만 이름은 "근거를 붙인 인출 훈련"이 정직하다(GD).
- **톤이 후퇴했다.** 제목이 "한양 도감"에서 "한능검 연표"로 바뀌었다. 화면은 "상자 1→2", "세션 끝내기" 같은 학습 앱 용어로 채워졌다. 正 인장과 먹 연출은 확인하지 못했다(CD).
- **(의견 차이)** CD는 독창성을 7점에서 5점으로 낮췄다(Timeline과 Leitner의 조합). GD는 학습 루프 자체는 좋아졌다고 본다(핵심 루프 5점 → 6점). 둘 다 맞다. 놀이성은 줄었고, 학습 구조는 늘었다.

### 2.2 학습·측정 설계 (사람 테스트 결과를 왜곡할 수 있는 것)
1. **반 구성이 계획과 코드에서 다르다(총괄이 확인).**
   - `m1-plan.md` §3.3: S1 = 01·02·04·06·09·11.
   - `prototypes/m1-timeline/js/config.js:54-55`: S1 = 01·03·06·07·10·11.
   - 계획은 같은 칸 카드(06 불교·07 율령, 04 낙랑·05 고국원)를 다른 반에 두었다. 코드는 둘을 같은 반에 넣었다.
   - D72의 근거("계획서 번호가 v2와 다르다")는 지금 계획서와 맞지 않는다. 계획서 표는 이미 v2 id를 쓴다(QA·GD 일치).
2. **시험 화면이 방식 A와 같은 형식이다.** pre·post 테스트가 A의 학습 동작(칸 고르기)과 같다. A가 이겨도 더 잘 가르쳐서인지 형식에 익숙해서인지 가를 수 없다(CD·GD 일치).
3. **두 방식의 노출 횟수가 다르다.** A에서 단서를 쓰면 상자 1에 남아 다음 세션에 다시 나온다. B는 "알았다"고 자기 평가하면 바로 승급한다(GD).
4. **3세션으로는 간격 반복을 검증할 수 없다.** 세 세션 안의 최대치는 상자 3이고, 상자 5는 가장 빨라도 세션 14다. 세 세션을 약 18분 안에 하므로 사실상 몰아서 하는 학습이다. 계획서의 PIVOT 조건 "상자 1~2에 갇힘"도 측정할 수 없다(GD 계산).
5. **천장 효과 위험.** 지문에 핵심어가 들어 있다(살수·국내성→평양·낙랑군·서안평). 1급 준비생은 pre 정답률이 높아서, "새로 익힌 카드" 분모가 반마다 0~2장이 될 수 있다(GD·CD 추정).
6. **카드별 함정.**
   - 서안평(03): 시험의 빈출 연결은 "서안평 = 미천왕 311"이다. 그런데 이 카드의 정답은 동천왕 242다. 지문만으로 둘을 가를 수 없다(CD).
   - 고국원왕(05): 직접 단서 "고국원왕 때, 371년"이 소수림왕 즉위 371과 겹친다(GD).
   - 살수대첩(11): 지문의 "살수"가 정답을 노출한다(QA).

### 2.3 UX·품질 버그
- **화면에 "null" 글자가 찍힌다(총괄 실행으로 확인, UX도 같은 지적).** 세션 결과 화면과 빈 세션 화면에서다. 원인은 `prototypes/m1-timeline/js/main.js:368`과 `:222-224`의 `replaceChildren(조건 ? el : null)`이다. `replaceChildren`은 null을 "null" 문자열로 바꾼다. `el()`은 null을 거르지만 `replaceChildren`은 거르지 않는다. 사람 테스트 모드의 빈 세션 화면(`app.study ? null : …`)에서도 참가자에게 보인다.
- **참가자가 "진행자" 버튼을 누를 수 있다.** 학습 화면에서 누르면 진행자 메뉴로 가고, "두 반 구성 보기"에 카드 제목과 연도가 있다. 접혀 있을 뿐 잠겨 있지 않다(UX).
- **모바일 테스트 화면에서 칸을 고를 때 지문이 스크롤 밖에 있다(UX).**
- **튜토리얼이 없다.** "상자"라는 말을 설명 없이 쓴다. 진행자 대본도 조작을 설명하지 않고, 시작 후에는 도움을 금지한다. 그래서 A가 낯섦 때문에 불리하다(UX).
- **재도전이 너무 쉽다.** 같은 세션 끝에 방금 정답을 본 카드를 다시 낸다. 상자 변화가 없으니 해는 없지만, "다시 풀기 성공"이 학습으로 읽히지 않게 해야 한다(총괄 관찰).
- **문서끼리 어긋난다(QA).** `STUDY.md`는 "사생활 보호 창 금지, self_rating knew/didnt_know"라고 쓰고, `m1-plan.md` §11은 "시크릿 창 권장, know/dont_know, retry 필드, 방식 B 없음"이라고 쓴다. 코드와 e2e는 STUDY.md 쪽과 일치한다.

### 새로 보인 문제 (차단 아님)
1. **방식 사이의 상자 비교가 같은 척도가 아니다.** 새 지표 "3세션 뒤 상자 2 이상 비율"에서 A는 정답 여부로, B는 자기 평가("알았다")로 상자가 오른다. 그래서 B는 과대평가로 높게 나올 수 있다. 판정에 쓰지 말고, 노출 횟수와 학습 진행의 참고로만 읽기를 권한다. 주 판정은 post1의 `king_chosen` 정답이다.
2. **일반 모드에서 "다음 세션에 다시"가 지켜지지 않는 경우가 있다.** 첫 세션에 틀린 05가 세션 2에 나오지 않고 세션 3에 나왔다. M1 설정(세션 6장, 새 카드 예약 6장)에서는 남은 새 카드가 도래 카드를 밀어낸다. 사람 테스트 모드는 반마다 6장이 첫 세션에 모두 들어가므로 영향이 없다. M2에서 세션 구성 규칙이나 안내 문구를 고친다.
3. 고국원왕 전사(05)의 "앞 왕을 고른다" 규칙은 시험 지식("고국원왕 때")과 어긋난 연결을 남길 수 있다. 계획대로 별도 집계하고, Day 1 정정 안내에서 "실제로는 고국원왕 때"라고 말해 주기를 권한다.

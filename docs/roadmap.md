# 로드맵: 한양 도감

> 기준 시점: 2026-11-04
> 근거 문서: `design/game-brief.md` (게임 내용), `project.yaml` (엔진과 설정).
> 이 문서는 진행 순서, 원칙, 결정 기록을 담는다. 게임 내용은 브리프를 따른다.

## 1. 비전
흩어진 유물과 사건 카드를 올바른 나라·시기에 배치해 삼국시대 도감을 완성하는 카드 퍼즐. "아는 만큼 도감이 채워지는" 뿌듯함이 목표다.

**성공 기준**
- **재미**: 카드 10장 시제품에서 "한 판 더"를 하고 싶어진다.
- **학습**: 해설을 읽은 뒤 같은 카드를 다시 맞힌다.
- **완성**: 12칸 도감을 모두 채우면 클리어한다.

## 2. 확정 사항
| 항목 | 내용 |
|---|---|
| 형식 | 카드 배치 퍼즐 |
| 범위 | 삼국시대만 MVP (고구려·백제·신라·가야 × 초기·전성기·후기, 12칸) |
| 카드 수 | 약 36장 (칸당 3장) |
| 실패 조건 | 먹물(오답 한도)이 0이 되면 해당 라운드 실패 |
| 대상 | 한국사를 가볍게 복습하려는 사람 |
| 아트와 오디오 | 고지도·한지 질감의 2D 일러스트, 국악 소품 |
| 엔진 | Godot 4.7, GDScript, Forward+, 2D 물리 (`project.yaml`) |
| 플랫폼 | PC, 키보드와 마우스 (카드를 마우스로 끌어 배치), hover 전용 상호작용 금지 |
| 테스트 | gdUnit4. 필수 테스트: 배치 판정, 먹물 규칙, 카드 데이터 로딩 |
| 설정 | rigor `minimal`, automation `guided`, 단계 Concept |
| 제외 | 삼국 외 시대, 전투, 경영, 멀티플레이, 음성 해설 |

## 3. 원칙
1. **사실 검증**: 모든 카드에 출처 필드를 두고 사람이 대조한다. 가야와 삼국 초기처럼 사료가 적은 구간은 "견해가 나뉨"으로 표기하고, 정답이 모호한 카드는 판정 대상에서 제외한다.
2. **데이터 분리**: 카드는 외부 JSON으로 두고 코드와 섞지 않는다. 시대 추가는 데이터 추가로 끝나게 한다.
3. **재미 먼저**: 카드 10장 시제품으로 재미를 검증한 뒤에 데이터와 아트를 늘린다.
4. **클라우드 제약**: 엔진 에디터는 실행하지 못한다. 헤드리스 테스트와 로컬 실행 확인을 병행한다. `godot`이 PATH에 없어 실행 경로는 `/settings`에서 지정해야 한다.
5. **한 번에 하나씩**: 질문, 선택지, 결정, 초안, 승인 순서로 진행한다. 파일은 승인 후 쓴다.
6. **보존**: 중요한 결정은 문서로 남기고 push한다. `production/session-state/active.md`는 gitignore 대상이라 컨테이너와 함께 사라질 수 있다.

## 4. 카드 데이터 스키마 (초안)
| 필드 | 설명 |
|---|---|
| id | 고유 번호 |
| type | 유물 / 사건 / 인물 |
| title, clue | 제목, 단서 문장 |
| answer | 정답 칸 (나라 × 시기) |
| explanation | 해설 |
| source | 출처 (교과서, 국사편찬위원회, 사료명) |
| verified | draft / checked / approved |
| difficulty | 난이도 (단서 수로 조절) |
| image | 일러스트 경로 (선택) |

## 5. 콘텐츠 검수
작성 → 출처 대조 → 두 번째 확인 → 승인. `verified`가 approved인 카드만 게임에 넣는다. 일러스트는 복식, 건축, 유물의 시대 고증을 따로 확인한다. 프로토타입의 카드 10장은 내용이 확인되지 않으면 `확인 필요`로 표시한다.

## 6. 진행 순서와 완료 조건
| 단계 | 명령 | 완료 조건 | 상태 |
|---|---|---|---|
| 1. 컨셉 | `/start`, `/brainstorm` | 브리프 작성과 push | [x] |
| 2. 엔진 | `/setup-engine` | Godot 4.7 + GDScript 기록 | [x] |
| 3. 검증 | `/prototype` | HTML 시제품(카드 10장)으로 가설 검증, PROCEED/PIVOT/KILL 판정 | [ ] 진행 중 |
| 4. 기술 | `/architecture-decision` 등 | 카드 데이터 로딩과 판정 구조 합의 | [ ] |
| 5. 제작 | `/create-stories`, `/dev-story` | 브리프 빌드 순서 2~4 (먹물, JSON 로딩, 도감 화면) | [ ] |
| 6. 콘텐츠 | 카드 작성과 검수 | 36장 approved | [ ] |
| 7. 마무리 | 진행 저장, `/smoke-check` | MVP 6개 항목 완료 | [ ] |

**3단계 상세 (프로토타입)**
- 방식: HTML. 이유는 타이밍이 아니라 "단서 난이도"가 가설이고, 클라우드에서 엔진을 실행할 수 없기 때문이다.
- 가설: 플레이어가 외우는 느낌이 아니라 추리하는 느낌을 받는다.
- 가장 위험한 가정: 단서의 난이도. 카드별 단서 수 차이로 확인한다.
- 판정 후 PROCEED면 Godot로 옮겨 4단계로 간다.

## 7. 리스크
| 리스크 | 대응 |
|---|---|
| 정답이 암기 퀴즈처럼 느껴짐 | 단서 수와 추론 구조를 프로토타입에서 확인 |
| 사실 오류 | 출처 필드와 검수 단계 필수 |
| 사료가 적은 구간(가야, 초기) | 모호한 카드 제외, 견해 표기 |
| 이미지 고증과 화풍 불일치 | 아트 방침을 먼저 고정, 카드별 프롬프트에 시대 키워드 |
| 엔진 버전 지식 공백 (4.5~4.7) | `docs/engine-reference/godot/` 참조, 로컬에서 실행 확인 |
| 클라우드에서 실행 확인 불가 | HTML 시제품, 헤드리스 테스트, 로컬 확인 병행 |
| 범위 확대 | 삼국만 유지, `/scope-check` |

## 9. 미정 항목
- 배포 계획. `project.yaml`에는 PC(Steam/Epic)로 기록되어 있으나, 개인용으로 만들지 공개 배포할지는 확정되지 않았다. 저작권과 출처 표기 수준이 달라진다.
- 일러스트 제작 방식(생성 도구)과 시작 시점
- 로컬 실행 확인 시점과 `godot` 실행 경로
- 도감 클리어 이후의 확장 순서(고조선, 고려 등)

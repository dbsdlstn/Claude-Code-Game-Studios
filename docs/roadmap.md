# 로드맵: 한양 도감 (v3, 한능검 수험생용)

> 기준 시점: 2026-11-05. D56(`docs/decision-log.md`)으로 전면 개정했다. 이전 로드맵(v0 보드 기준)은 git 기록(`7fd5608` 이전)에 있다.
> 근거: `design/game-brief.md`(v3), `design/card-data-schema-v2.md`, `design/leitner-spec.md`, `production/playtest/m1-plan.md`, `docs/reviews/evaluation-hanneungeom.md`.
> 이 로드맵의 방향 전환은 디렉터 세션이 위임받아 확정했고 사용자가 검토한다.

## 1. 비전과 성공 기준
이름이 지워진 사료 속 장면을 읽고 왕대 연표에 꽂으며, 틀린 카드는 간격 반복으로 다시 만나 한능검 고대사를 익히는 수험생용 학습 게임.

**성공 기준(M1 사람 테스트로 판단)**: 같은 카드를 단순 플래시카드로 배울 때보다 (1) 근거를 말할 수 있고, (2) 다음 날 재인출이 같거나 높고, (3) 다시 하고 싶은 의사가 낮지 않다.

## 2. 확정 사항
| 항목 | 내용 |
|---|---|
| 대상 | 한능검 심화(1급 목표) 수험생 |
| 핵심 루프 | 사료 앞면 → 왕대 연표에 꽂기 → 단서는 숙련도 비용 → 해설 → Leitner 간격 반복 → 숙련 도감 |
| 모드 | 학습(M1·본 구현), 모의시험(후속), 클래식 v0 보드(동결) |
| 플랫폼 | 모바일 웹 우선(세로 390px부터). Godot는 동결, CI만 유지 |
| 범위 확장 순서 | 고구려 12장(M1) → 삼국 전체 → 남북국 → 고려. 조선 이후는 로드맵 밖 |
| 데이터 | 외부 JSON, 스키마 v2(`assets/data/cards/v2/`) |

## 3. 원칙
1. **사실 오류는 치명 결함**: 아래 4절의 품질 게이트를 통과하지 않은 카드는 수험생에게 내보내지 않는다.
2. **검증 먼저, 확장은 나중**: 루프가 플래시카드보다 낫다는 사람 데이터가 나오기 전에 카드 수를 늘리지 않는다.
3. **데이터 분리**: 카드·앵커는 JSON. 시대 추가는 데이터 추가로 끝나야 한다.
4. **번역문 비인용**: 사료 지문은 원문을 근거로 직접 풀어 쓴다.
5. **스크립트는 관찰만 낸다**: 검증기는 판정이 아니라 위반 목록을 낸다.
6. **보존**: 결정은 `docs/decision-log.md`, 계획은 `docs/`, `production/`에 남기고 push한다.

## 4. 사실 확인 품질 게이트 (평가 보고서 5절 채택, D56 8)
1. 모든 카드·앵커는 **서로 다른 두 사람**이 확인한다(`verification`).
2. 출처는 1차 자료의 권·조 단위(한국사데이터베이스 URL 포함)로 적는다.
3. 한능검 기출의 표기(사건명, 왕명)와 대조한다.
4. **출처 URL이 없으면 release 검증이 실패**한다(스키마 R1~R3).
5. 지문·연도가 바뀌면 `verified`가 자동 해제된다(`content_hash`).
6. 확인자는 사용자가 정한다. 모델은 확인자가 될 수 없다.

## 5. 마일스톤

### M0. 기반 (완료)
v0 웹/Godot 프로토타입, 평가 보고서, D56 전환, 브리프 v3, 스키마 v2·Leitner 명세·M1 계획 초안. 
**완료 조건**: 문서 5종이 저장소에 있다. (충족)

### M1. 고구려 12장 사람 테스트
- **내용**: 앵커 10 + 사료 카드 12(스키마 v2 초안), HTML 프로토타입(연표 꽂기, 단서 비용, Leitner), 같은 카드를 플래시카드와 비교(`m1-plan.md`).
- **선행**: 카드·앵커 2인 확인(또는 "검증 전" 고지를 붙인 방식 비교만), 프로토타입 빌드, 수험생 1~2명 모집.
- **완료 조건**: 기록 양식 14가 채워지고 판정(PROCEED/PIVOT/차이 없음/KILL/NOT ASSESSED)이 내려졌다.
- **되돌림 조건**: 다음 날 유지에서 연표 방식이 플래시카드보다 낮거나(2장 이상), 느리고(카드당 시간 2배 초과), 둘 다 싫어하면 (C)를 접고 평가 보고서 (A)/(B)와 목표를 다시 정한다.

### M2. 스키마 v2 확정과 학습 모드 본 구현
- **내용**: M1 결과를 반영해 스키마·Leitner 명세 확정, 웹 학습 모드 구현(모바일 우선, 저장, 숙련 도감, 오답 노트), 검증기 v2(`tools/validate_cards_v2.py`, V1~V15·R1~R3).
- **완료 조건**: 고구려 12장으로 세션 시작~저장~재방문이 동작하고, 검증기가 변형 검사(mutation)에서 위반을 모두 잡으며, 390px 화면 증거가 `production/qa/evidence/`에 있다.
- **되돌림 조건**: 구현 비용이 계획의 2배를 넘으면 범위를 줄여 총괄에 올린다.

### M3. 삼국 전체
- **내용**: 고구려·백제·신라·가야 왕대 앵커와 사료 카드. 범위는 한능검 출제 주제 목록(공식 정보 원문 확인 후)을 기준으로 정한다.
- **완료 조건**: 모든 카드가 2인 확인과 release 검증을 통과하고, 덱 용량(대략 50장/일 1세션 기준, `leitner-spec.md` §7)에 맞춘 세션 구성이 검증되었다.
- **되돌림 조건**: 사실 확인 처리량이 제작 속도를 막으면 카드 수를 줄이고 확인자 인력을 먼저 해결한다.

### M4. 남북국
- **내용**: 통일신라·발해 앵커와 카드.
- **완료 조건**: M3와 같은 게이트. 두 나라가 같은 연표에 공존하는 표현(칸 해상도)이 사람 테스트로 확인되었다.

### M5. 고려
- **내용**: 왕대·제도 중심 카드. 고려는 연표 외에 제도 설명 카드가 늘 것으로 보여 카드 유형 확장 여부를 시작 시점에 결정한다.
- **완료 조건**: M3와 같은 게이트.

### 후속 후보 (일정 없음)
모의시험 모드(5지 선다, 시간 압박), 시험 직전 모드, 클래식 v0 보드 복귀, 일러스트·소리, 배포.
